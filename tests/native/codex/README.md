# Opt-in Codex checks

Compatibility target: Codex CLI/app-server **0.163.0**. These checks are manual; ordinary `musts`/release checks do not enable ignored tests or run native inference.

Run one heavy suite at a time through Bazel. The combined Codex slice used during implementation is:

```sh
bazelisk test //crates/alondrad:alondrad_test //agent-host:codex_native_test \
  --test_arg=codex --test_arg=--include-ignored --test_arg=--test-threads=1 \
  --test_env=CODEX_NATIVE_EXECUTABLE=/opt/homebrew/bin/codex \
  --local_test_jobs=1 --test_output=streamed --test_timeout=300
```

The explicit executable is essential: an ordinary run without it is not native proof. All credentials are synthetic; model responses come from a loopback double. The suites own their temporary homes and processes, fence external access and never use the user's daemon, accounts, Keychain or hosted service.

Evidence levels:

| Suite | Actual components | Double | Demonstrates |
| --- | --- | --- | --- |
| `agent-host:codex_session_test` and daemon Codex tests | Host, owner, store, normalization and receipts | Native app-server | Correlation, replay, controls, positive consumption and failure boundaries |
| `agent-host:codex_native_test` | Codex0.163 app-server and host policy | Loopback model and fixture MCP | Effective offered tools, restrictive configuration and hostile overrides |
| `an_actual_codex_cli_*` in `sdk_owner/codex_tests.rs` | Codex0.163, host, real owner/store, Alondra MCP | Loopback model | Actual input/turn behavior and plan/question/result flow |
| `process_adoption` in `sdk_owner/codex_process_tests.rs` | Production daemon, host and OS processes through two SIGKILL/restarts | Native app-server with a permission or barrier-held child | Durable adoption without replay, child/process survival and permission continuity |

Process adoption uses candidate bytes and a deterministic native double. It does not demonstrate a previous published Codex release or replace the signed upgrade rehearsal. A candidate test cannot invent a historical artifact.

Native `badRequest` is not proof that a model is unavailable to an account. Codex0.163 `TurnError` lacks an exact rejected-model identity; broad messages must not poison model/account availability. Preserve the requested selection and use a task-specific actionable rejection when precise native evidence is absent.

Fixture compatibility is checked against release source `83086188ae0614bd882818ff1aa23f3194962012` and schemas generated by the installed0.163 executable. Built-in `openai` cannot be redefined under `model_providers`; the loopback doubles use the supported top-level `openai_base_url` with `/v1`, preserving managed authentication. Discovery returns an HTTPS workspace origin as metadata; the explicit `/v1` endpoint keeps inference in loopback.

The doubles count only Responses requests, acknowledge unrelated telemetry separately, and emit the full Responses SSE content/argument deltas. `features.enable_request_compression=false` is a supported stable fixture setting so the local JSON double does not need a Zstd decoder. Production transport is unchanged. Optional native app/plugin failures and transient errors are not terminal business failure; the journey checks the required Alondra MCP, failed terminal turns and durable cards/results.

The native role inventory exposed default-on `image_generation`; the orchestrator now forces its canonical flag and legacy alias off after inherited settings. The exact eight-tool assertion remains strict. See [the pinned feature registry](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/features/src/lib.rs#L1692).

Actual default-model role proof: invocation b27d2775-4551-446f-b3ca-c5271a89ca85 selected native gpt-6.1-sol and verified the exact callable ALL_TOOLS registry, not only the outer exec/wait rendering. The model can mandate CodeModeOnly despite feature flags (pinned core/src/tools/mod.rs57–77). Pure rendering cannot grant excluded native effects. The runtime proof checks missing effect helpers, imports, ambient host globals and image/file/HTTP access.

`//agent-host:codex_native_cells_test` is a separate opt-in deterministic native-cell case. A held fixture MCP callback permits the first root turn to complete; its release must not retire the live cell. A second legitimate input and exact native wait must produce correlated terminal evidence. It has no fixed-duration race and is outside ordinary MUSTS.
