# F2 integration contract

This branch contributes the task and schedule reducers. H owns the app composition change.

1. Add `//apple/Features/Tasks:AlondraTasksFeature` to both `AlondraiOSEntry` and `AlondraMacEntry` in `apple/BUILD.bazel`. Keep each scene's `StoreOf<TaskBoardFeature>` and each task route's `StoreOf<TaskDetailFeature>` local to that scene; send `.identityChanged` when the root identity or presentation epoch changes.
2. Project each accepted `FleetStore.board` snapshot through `TaskBoardProjection(board:canArchive:hasSnapshot:)` into `.boardChanged`. The rows remain value projections of the same accepted board. The board reducer owns expansion, selection and archive progress. Do not let a view call `FleetStore.archiveCompleted()` directly.
3. Supply `TaskOperations` at composition from `CommandGate` results, preserving `.confirmed`, `.unknown(command.id)`, `.rejected(message)` and `.obsolete` as distinct `TaskMutationOutcome` values. Do not adapt the legacy `FleetStore` Boolean result because that loses the uncertainty required for the UI. On Mac, pass these through `MacAppSync.runMutation` so a discarded window cannot publish an old result. The reducer treats POST confirmation as acknowledgment only; the sync snapshot decides the task transition. Render `.unknown(id)` as an uncertain result and keep the action disabled. A later snapshot or task history change alone cannot unlock it; only the journal owner sends `.commandReconciled(id)` after resolving that exact record.
4. For the iOS and Mac task detail routes, send `.taskChanged(task)` on accepted changes. Bind confirmation and `isActing` to the reducer, and render `detail` from its state. Child navigation for PRs/reports can retain the current presentation until G1/G2. Use `successfulActionCount` for iOS sensory feedback. Keep `TaskDetailFeature` alive only while its route exists.
5. Split `apple/Shared/Sources/ScheduledTasks.swift` into DTOs still owned by `AlondraShared` and a SwiftUI view in the platform UI module. The current shared view creates clients and stores network state in `@State`; replace this with a `StoreOf<ScheduleFeature>` and action-only UI. Preserve the existing schedule editor controls and localized messages while binding them to `draft`, `optionSpecs`, `projects`, `isSaving` and `error`. The view must not retain `AlondraClient`.
6. Supply `ScheduleOperations` from the active identity's service/use case. Every schedule mutation (`save`, `run`, `delete`) returns `TaskMutationOutcome` from the same credential-scoped command guard and durable uncertain-result journal as other commands. The reducer permits only one in-flight mutation per schedule across save/run/enable/delete, then preserves an unknown journal ID per schedule (or the new-schedule slot) across refresh/editor dismissal. Render `uncertainByTarget` at each affected schedule and `lastMutationOutcome` for the latest action; an unrelated successful action must not hide an unresolved schedule. Only the journal owner sends `.commandReconciled(id)` after resolving that exact record; a raw `AlondraClient` closure is insufficient for release.
7. Verify Bazel builds of `//apple:AlondraiOS` and `//apple:AlondraMac`, then use MAV on iOS and Mac for task navigation and schedule create/run/error flows. The feature target alone proves reducer behavior, not app wiring.

The integration must remove these direct view mutations: `TasksTab` archive/withdraw, both `TaskDetail` cancel/reopen/details state, and `ScheduledTasksView` refresh/save/run/delete/options/projects. It must not add a `URLSession` or client to SwiftUI views.
