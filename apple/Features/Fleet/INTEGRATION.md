# F3 integration contract

H owns `apple/BUILD.bazel`, `FleetTab`, `NodeDetail`, `FleetView` and `Mac NodeDetail`. This PR adds only the shared feature logic and its Bazel module.

1. Add `//apple/Features/Fleet:AlondraFleetFeature` to both app entry targets. A process-owned accepted `Overview` becomes `ProjectFleetUseCase.execute(overview, visibleInboxIDs: Set(fleet.inbox.map(\.id)), sequence: nextSequence)`. `nextSequence` is a monotonically increasing local counter for **each** accepted projection, including a change to hidden cards with the same overview; never use daemon `tick` for it. Re-project when hidden cards change even if the overview does not. Deliver `.snapshotChanged` to every visible Fleet and NodeDetail store. Send `.snapshotUnavailable` when the current identity disconnects, retaining visible data with a stale indicator; send `.identityChanged` before switching server, signer or credential revision. The root must only send snapshots accepted by its SyncSession identity/generation gate. Both reducers ignore older delivery sequences while accepting a lower daemon tick after restart, with or without an offline event.
2. Keep one `StoreOf<FleetFeature>` per scene/window. Bind search to `.searchChanged`, selection to `.selectNode`, and close confirmation to `.closeRequested` / `.closeConfirmed` / `.closeCancelled`. Render `filteredSections`, `snapshot.orchestrator`, `selectedNode`, `isStale`, `closingIDs`, and `closeOutcomeByID`. The reducer does not fetch previews or threads when search/selection changes.
3. Create `StoreOf<NodeDetailFeature>(initialState: .init(sessionID:))` only for the selected node route. Send `.snapshotChanged`, `.appeared` on presentation and `.disappeared` on removal. The detail loads threads immediately and every ten seconds only while visible. Render `entry`, all `tasks`, `threads`, stale state and error/outcome state. `.shouldDismiss` follows a confirmed close; rejection keeps the node open and displays the server refusal.
4. Supply `NodeOperations` at each root from the active identity's transport service and `CommandGate`. `close` must use `.closeNode(session)` and preserve confirmed, rejected (especially `CloseRefused.message`), unknown(journal ID), and obsolete separately. `send` must reserve `.send(session)` under the active scope before uploading `NodeMessage.files` and calling `AlondraClient.send`; a failure to upload is a rejected/unknown result according to the gate. H must not adapt the legacy Boolean `FleetStore.perform`, which erases uncertain results. A raw HTTP closure is insufficient. Only the journal owner sends `.commandReconciled(id)` for the exact command; an overview refresh must not clear unknown.
5. Node composer views bind text and picked files to `message`, `files`, `.messageChanged`, `.filesChanged`, `.sendTapped`. Convert picked bytes to `NodeFile` without creating `AlondraClient` or calling `Attachments.storedIDs(using:)` from a view. The operation uploads under the command service. Keep Mac drafts scene local, preserving existing window isolation. The reducer clears a draft only if it still matches the acknowledged message; typing during a send is preserved. File size/preparation can reuse `AttachmentFile` in the service or a UI-independent use case.
6. The selected node route owns thread polling. `NodeOperations.threads` maps the node route's optional activity; nil means an older daemon and falls back to overview activity/tool. A transport failure retains the last displayed ledger. The app root must not create another timer for this route.
7. Keep existing iOS/Mac visual presentation, accessibility and task/card navigation. Replace search/filter and close/send/threads logic currently in views with feature state/actions. Machine/usage presentation remains in the scene root; do not duplicate their polling. A preview or detail network request must start only after selection.
8. Build iOS, Mac and extension after wiring; run MAV for search, multi-task node, rejected close, send success/error, stale reconnect and thread detail on both platforms. The module's tests prove behavior, but do not prove app wiring.
