# D1b command boundary

`CommandGate` records only the operation kind, current server/device/credential scope, card ID and an unknown result. An unresolved card blocks every action on that card, including a different notification button after relaunch. The send closure is held only for its first execution and is never saved for replay. `FleetStore` currently bridges legacy call sites into this boundary; the TCA use cases should submit typed commands directly when each feature migrates.

The current daemon has no general idempotency key or duplicate-result contract. A timeout, lost connection or cancellation after dispatch is therefore an unknown outcome. Reconnection may fetch a snapshot, but must not resend a mutation. The composer keeps its draft and an affected card becomes visible again so the user can inspect server state before deciding to act again. A fresh server/credential generation clears presentation state and invalidates in-flight results.

`FileCommandJournal` persists non-executable metadata in each app's Application Support directory. The iOS process and each Mac window restore warnings at launch and after an identity change; `FleetStore` projects them to the existing warning UI and removes the durable record before dismissing it. `submit` also restores lazily and refuses to send if the journal cannot be read or the pending record cannot be written and synced. A `pending` entry is shown as unknown after relaunch. A matching unresolved command is blocked until the user explicitly reconciles and dismisses it. The file journal reserves a command under a container lock, so app and extension can share the same directory when their entitlement allows it; the caller must use exactly that directory in both processes. A journal file has a UUID, action kind and target identifier, item ID, server/device/credential revision/generation, and pending/confirmed/unknown state; it has no request body, signature, credential or closure. Pass a canonical base URL without userinfo, query or fragment and an opaque credential revision, never a secret. The notification response path now submits through this same app-owned gate; its real APNs delivery/actions still require MAV verification before release. A missing snapshot item or HTTP 404 is not proof that a write did not occur.

Before enabling any automatic retry, agree with the backend on key placement, duplicate response semantics, retention, and reconciliation for every mutating route. The key must bind immutable payload bytes and the authenticated device/server identity. Test a lost HTTP response after the server commits the operation, then verify exactly one side effect across reconnect and process restart.

The root can project `SyncSession` into the temporary `FleetStore` with `apply(_:)` and `setConnection(_:)`; it must use a single app-owned `CommandGate` and a monotonically increasing `CommandScope.generation` across Mac windows. On a credential change, call `await gate.use(nextScope)` and `fleet.use(newClient, commandScope: nextScope)` in each window, even if URL and device ID remain equal. The gate rejects a delayed old `use` call, so it cannot roll back to an earlier identity. It must not start `FleetStore.run()` once SyncSession owns polling.
