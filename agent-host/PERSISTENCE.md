The private Rust launcher must independently acquire File::try_lock on the stable0600 state_dir/host.lock inode before writing/fsyncing bounded bootstrap metadata, opening the journal or launching. It moves that SAME locked File as stdin through safe Stdio::from(File), drops Command and all daemon copies after handoff, and never unlocks or replaces/unlinks the inode. The host reads fd0 with bounded positional readSync, retains it through journal shutdown and verifies inode/owner/mode, full worker fence/execution and the actual Node executable and bundled entrypoint hashes. fstat is not evidence that the lock was acquired: that obligation belongs to the private launcher and actual subprocess tests. Native SDK children receive three fresh pipes, not inherited stdin. The native session UUID is a Claude-only immutable conversation mapping, distinct from generic ConversationId and per-input MessageUuid mapping. The current bootstrap supports only node_bundle with hermetic Node24.19.0; persistent SEA and shipping identity/distribution remain required gates. Node-base build metadata cannot authenticate repacked SEA bytes.

Hello is a claim checked against the daemon-owned manifest, not authentication. The fresh challenge and fixed-order length-prefixed HMAC bind the entire expected fence/execution/artifact identity and a newly committed owner generation. The Attached response has a separate host-direction HMAC over the full pending Attach transcript and request proof. The Rust client compares its own committed expected identity/generation and verifies that response MAC before commands/capabilities; an echoed controller proof cannot authenticate the host. Every reconnect needs a new generation. A higher authenticated grant is fsynced before replacing the writable lane; old queued work checks the current lane again after await, at actual native spawn, and immediately before SDK input/decision/control calls. Revocation after a possible handoff preserves uncertainty. It cannot retroactively prove that no effect occurred.

Commands retain the exact original payload bytes and digest across adoption. The fsynced append-only journal contains only technical command identities, receipts, ordered raw observations, owner grants and daemon ACKs. It keeps only what is still needed, for any length of node: the events after the last ACK, and the commands the owner may still send again. The owner sends nothing after a command before it has stored that command's outcome, and only sends again a command whose outcome it never stored, so a command with a final receipt (offered, applied or rejected) followed by a later owner frame (an ACK or another command) is settled: it leaves the journal, and its digest and final receipt stay in memory to answer a copy that arrives anyway. Once the file passes 4MiB at an ACK and at least half of it is no longer needed, it is rewritten to outbox.next with the ACK's owner grant, that ACK, the current grant, the unsettled commands with their receipts and the unacknowledged events, fsynced and renamed over outbox; an outbox.next left by a cut rewrite is removed at open. A compacted journal starts at its ACK, so its first event follows that cursor. At most 256 unsettled commands and 64MiB of unacknowledged evidence are held; past them, or on an I/O failure, the host marks uncertainty and blocks further effects instead of evicting evidence. A prior command after host restart requires positive reconciliation; no automatic SDK offer replay or claim that an old child/effect ended follows from restart.

Daemon disconnect only detaches its lane: it does not close the SDK, kill native background work or allow pending permissions. SDK permission callbacks remain owned in the surviving host. Replay sends persisted observations after the last acknowledged cursor, and receipts carry technical phases. Rust commits observation/domain/card evidence before ACK. Neither ACK, receipt, singular native UUID echo nor deleting the Session capacity set is InputConsumed. The external fake can produce failed-delivery singular UUID echo, a real consumed-list result, owned background continuation and a pending permission across disconnect. Those paths still need actual SDK/controller execution evidence.

The host creates the owned0600 Unix endpoint under canonical0700 directory and umask077; this endpoint carries all Frames. Stale owned socket removal requires the privately transferred exclusive lock, never PID/age. Host stdout/stderr are bounded diagnostic sinks and may drop ordinary output under pressure or after daemon pipes close. One fixed post-listen diagnostic line, Alondra host: socket listening, is a bootstrap wakeup written without the ordinary drop wrapper. It conveys no control/identity/authority. The Rust reader keeps at most4KiB line scratch and16KiB tail, discards oversized lines and limits all launch connection attempts, including the initial attempt, to8; only Unix expected-manifest/challenge/HMAC plus committed fresh owner generation authorizes commands. Startup deadline/EOF/noisy or forged hints remain explicit uncertainty, never evidence of native death or permission to kill/replay. Reconnect uses the existing socket, without rotating/relocking the live bootstrap. The fixture entrypoint injects console/direct stdout and late warnings through the same real host implementation. Native stdin/stdout/stderr stay separate SDK pipes; private FD inheritance and disconnect continuity still require subprocess proof. The existing child-exit barrier remains authoritative: post-spawn error or cancellation alone does not complete finished. Explicit stop waits for actual native exit; no business closure or remote exit is invented by the host.

The outstanding-send set is only technical capacity accounting.
